# バーチャルゲームセンター 設計メモ（v0.4, 2026-10-25。Q1〜Q7 決定、§7 店内の BGM は v0.2.0、§8 クレーンゲーム・§9 ポスター欄・§10 チャットのピン止めは v0.3.0、§11 スマホのレイアウト・§12 コミュニケーションノート・§13 機能追加要望箱は v0.4.0）

Web ブラウザから入れる、クオータービューのバーチャルなゲームセンター。参加者は自分のキャラクターを歩かせ、チャットとエモーションでやりとりする。
ゲームの筐体には YouTube の配信 URL と宣伝（イベント名・ゲーム名・プレイヤー名・備考）を設定でき、どこで何が配信されているかが店内を歩いて分かる。
**Android アプリではなく Web アプリ**。仮の名前・フォルダ名は `virtual_arcade`。

> ✅ = ユーザー指定、🔧 = 叩き台の案（要確認は末尾の表）

---

## 1. 画面（PC・フル HD 1920×1080 向け ✅）

```
┌──────────────────────────────────────────────┬──────────────┐
│  クオータービューの店内（キャラクター・筐体・壁の大画面）     │  チャット      │
│                                              │  （発言・案内） │
│   ┌壁の大画面: 配信一覧┐                        │              │
│   └─────────────────┘                        │              │
│    [筐体][筐体][筐体]   ← 画面に配信中の印・サムネイル │              │
│        🙂 ← 自分        😀 ほかの人（頭上に名前・吹き出し）│              │
├──────────────────────────────────────────────┤              │
│ エモーション [👍][😂][😮][👏][❤]  移動: クリック / WASD    │ [発言欄]      │
└──────────────────────────────────────────────┴──────────────┘
```

- **入室**：名前（20 文字まで）とキャラクターの見た目（色・帽子など数種）を選ぶだけ 🔧。アカウント登録なし（ブラウザに保存した鍵で同じ人と見分ける）。
- **移動** ✅：床をクリックした所へ歩く（経路探索）＋ WASD / 矢印キー 🔧。ほかの人の動きもリアルタイムに見える（WebSocket）。
- **チャット** ✅：店内全体に届く。右の欄に流れ、**発言した人の頭上に吹き出し**（数秒。続けて発言したら差し替え。長い文は吹き出しでは省略）。
- **エモーション** ✅：ボタンで頭上に大きな絵文字・動き（手を振る・拍手など）。

## 2. 筐体

- 店内に筐体を並べる（🔧 初期は 12〜20 台。並びは店のレイアウトのデータで決める）。
- **設定できるもの** ✅：
  - YouTube の配信 URL（`youtube.com/watch?v=…`・`youtu.be/…`・`youtube.com/live/…` だけ受け付ける）
  - 宣伝：イベント名（参加型対戦・大会など）、ゲーム名、プレイヤー名、備考
- **誰が設定できるか** ✅：管理者とプレイヤー。🔧 案：空いている筐体を「使う」と、その人が持ち主になって設定できる。持ち主が外す・時間切れ（例 6 時間更新なし）で空きに戻る。管理者はどの筐体も変更・解除できる。
- **店内での見え方** ✅：簡易表現で「配信している」ことが分かる。
  - 🔧 筐体の画面に YouTube のサムネイル画像（`i.ytimg.com` の静止画。API キー不要）を貼り、「LIVE」の札と光の点滅。頭上に宣伝の短い札（イベント名・ゲーム名）。
  - 🔧 筐体に近づく / カーソルを置くと、宣伝の全文（イベント名・ゲーム名・プレイヤー名・備考）の吹き出し。
- **筐体の画面に配信そのものを映す**（希望・難しければ見送り）：
  - 🔧 技術的には、筐体の画面の位置に小さな YouTube の埋め込み（iframe）を重ねれば映せる。ただし同時に何本も再生すると重く、音・自動再生の制限もある。
  - 🔧 案：ふだんはサムネイル、自分が近くにいる筐体 1 台だけ小さく埋め込み再生（音なし）にする。
- **筐体にアクセス** ✅：筐体をクリック → 「この中で視聴する（視聴画面）」か「YouTube で開く（新しいタブ）」を選ぶ。
  - 視聴画面 🔧：大きな埋め込みプレイヤー＋宣伝＋その場のチャット（店内のチャットと同じ欄）。［店内に戻る］。視聴中も店内では自分のキャラクターが筐体の前に座っている。

## 3. 壁の大画面 ✅

- 店の壁に大きな液晶画面。**いま配信中の筐体の一覧**（サムネイル・イベント名・ゲーム名・プレイヤー名）を順に表示（🔧 数秒ごとに切り替え、または一覧表）。
- 🔧 クリックすると一覧の拡大表示 → 選んだ筐体へ歩いて行く / そのまま視聴画面。
- 🔧 管理者のお知らせ（大会の予定など）も流せる。

## 4. 管理者

- 🔧 管理者の合言葉（サーバの設定）で管理者になる。できること：筐体の設定・解除、お知らせ、チャットの発言の削除、人を退室させる・入室を止める。

## 5. 技術構成 🔧

| 部分 | 案 |
|---|---|
| 構成 | npm workspaces：`shared`（型・店のデータ・経路探索）/ `server` / `client` |
| クライアント | TypeScript + React + Vite。店内の描画は Canvas（PixiJS などの 2D）でクオータービュー（キャラクター数十人でも軽く） |
| サーバ | Node.js + Express + ws（位置・チャット・筐体の配信）、SQLite（筐体の設定・お知らせ・チャットの直近） |
| YouTube | URL から動画 ID を取り出す・埋め込み（`youtube-nocookie.com`）・サムネイル。配信中かどうか・タイトルの自動取得は 🔧（API キーが要る。最初は持ち主が設定した内容をそのまま出す） |
| 公開 | 🔧 既存のサイトの別のパス（例 `https://example.com/arcade/`）。Apache のリバースプロキシの下に置く |

## 6. 公開するときの注意（🔧）

- 誰でも入れるチャットになるので、NG 語・回数制限・管理者の削除と退室は最初から入れる。
- 筐体に設定できるのは YouTube の URL だけ（ほかのサイトへの誘導にしない）。宣伝の文字にも NG 語。
- YouTube の埋め込みは YouTube の利用規約に従う（埋め込みが無効な配信は「YouTube で開く」だけ）。

## 7. 店内の BGM（v0.2.0、2026-10-25 ✅ ユーザー指定「店内に BGM を流しましょうか」）

経緯：近くの筐体の小さな配信に音を出す案はやめた（✅）。小さな配信は今までどおり**音なし**で、BGM とは関係しない。

### 7.1 曲 ✅

- **同梱の曲（既定）**：魔王魂のアコースティック 5 曲（`アコースティック02 / 11 / 46 / 50 / 52`。曲名は魔王魂のサイトの表記）。✅ ユーザーが `bgm/` に mp3 を置いた。
  店内ではこの 5 曲を**順番に**流す（1 曲 = イントロ + 本体 2 周。🔧 叩き台）。
- **合成の曲**：権利の心配がないよう、Web Audio API でブラウザの中で合成して演奏するオリジナル 3 曲（チップチューン。矩形波 25% / 12.5% / 50%・三角波・ノイズのドラム）。
  一覧から選べる（選んだ曲をくり返す）。曲はデータ（`shared/src/songs.ts`。音符の並び・テンポ・音色）で、足すときは同じ形で書いて `npm test` で検証する（`shared/src/bgm.ts` の先頭に書き方）。
  | 曲名 | 雰囲気 | テンポ・長さ |
  |---|---|---|
  | ネオン・スタート | 明るい店内のメイン（C メジャー、25% 矩形波のメロディ・三角波のオクターブのベース・12.5% のアルペジオ） | 136 BPM・24 小節（約 42 秒） |
  | ミッドナイト・ロビー | 落ち着いた夜の店内（A マイナーのセブンスの和音・三角波のパッド・こだまのかかったメロディ） | 92 BPM・16 小節（約 42 秒） |
  | トーナメント・ファイア | 大会の盛り上がり（E マイナー、16 分で刻むベースとハイハット） | 152 BPM・24 小節（約 38 秒） |
- **自分の曲への差し替え**（任意）：サーバの `data/bgm/`（環境変数 `BGM_DIR`）に音声ファイル（mp3 / ogg / m4a）を置けば一覧に加わる。曲名・作者は `data/bgm/bgm.json`。
  ファイルの権利は置く人の責任（`data/bgm/README.md`）。

### 7.2 ループ（同梱の曲 ✅）

- `tools/bgm/loop_bgm.py`がループ点 A〜B を自動で探し（`tools/bgm/loops.json`。git には入れない）、
  イントロ（頭〜A）と本体（A〜B。末尾で B の手前と A の手前を短く重ねて、最後のサンプルの次が先頭へ連続につながる）の Ogg Vorbis を `data/bgm/` に書く。
- `tools/bgm/loudness.py --target -17 --apply` で 5 曲の音量（統合ラウドネス）を −17 LUFS 前後にそろえ、`bgm.json` の `gain` に書く。合成の曲も −17 LUFS 前後になるよう曲ごとの `gain` を付けた。
- ブラウザは Web Audio で、イントロのバッファ → 本体のバッファ（`AudioBufferSourceNode.loop = true`、`loopEnd` = 本体の長さ）をサンプル単位でつなぐ。
  `<audio loop>` は継ぎ目にすき間が出るので使わない。
- ブラウザ（Chrome の decodeAudioData）が短い Vorbis の末尾を削ることがあった（0.15 秒のイントロで 87 サンプル）ので、ogg の後ろには続きの音を 0.25 秒足し、
  正しい長さを `bgm.json` の `introSec` / `bodySec` に書いてその長さで鳴らす。
- デコード済みのバッファは今の曲と次の曲の分だけ持つ（次の曲は切り替えの 25 秒前から読み込む）。曲の切り替えは 0.6 秒のフェード。

### 7.3 再生

- **自動再生の制限**：入店のボタンを押した操作の中で AudioContext を作る。再読み込みで自動入店した場合は最初のクリック・キー入力で始める。それまでは下のバーに「🔇 クリックで BGM」。
- **操作**（下のバーのエモーションの左）：［🔈/🔇］・音量のスライダー（既定 25%）・曲名とクレジット（クリックで曲の一覧）・［次の曲］。
  設定（音量・消音・曲）は localStorage `va:bgm`。
- **視聴画面の動画** ✅：大きな埋め込みで動画が**実際に再生を始めた瞬間**に、BGM を 1.8 秒でフェードアウトして止める。視聴画面を閉じて店内に戻ったら 1.5 秒でフェードインして続きから。
  動画の一時停止・終了だけ（視聴画面は開いたまま）では戻さない。
  - 検出：埋め込みの URL に `enablejsapi=1&origin=<このページのオリジン>` を付け、埋め込みへ `{"event":"listening"}` を送って、
    返ってくる状態（`onStateChange` / `infoDelivery` の 1 = 再生中）を `message` で受ける。送り元の窓（この埋め込み）とオリジン（youtube-nocookie.com / youtube.com）を確かめる。
  - 予備：状態が 1 度も届かなければ、視聴画面を開いて 5 秒で止める（状態が届いているのに再生していない = 自動再生が止められた ときは止めない）。
  - 判断は純粋な関数（`client/src/audio/videoDuck.ts`、テストあり）。
- **お知らせのチャイム**：管理者のお知らせが増えたら短いチャイム（3 音）を BGM とは別に鳴らす。消音の設定に従う。
- タブが裏に回っても鳴り続ける。合成の曲は先読みのスケジューラ（見えているときは 0.3 秒先、裏では 1.5 秒先まで予約）で、タイマーの揺れに強い。

### 7.4 曲名・クレジット・規約

- 合成の曲は「オリジナル（このアプリのために作曲）」。同梱の曲は「**音楽：魔王魂（ループ・音量の調整のため編集）**」を BGM の操作の曲名の下・曲の一覧・入店の画面に出す。
- 魔王魂の規約（https://maou.audio/rule/ ）：クレジット表記必須・改変したらその旨を記載（ループのための切り出し・つなぎ目の重ね・
  再エンコード・音量の調整をしたので「ループ・音量の調整のため編集」）・**曲単体の再配布は禁止**（曲のファイルを単体で落とせる一覧ページは作らず、BGM として流すだけ。
  元の mp3 も加工した ogg も公開リポジトリに入れない。`npm run package` の tar には加工した ogg と一覧だけを入れる）。

## 8. クレーンゲーム（v0.3.0、2026-10-25 ✅ ユーザー指定）

ユーザーの要望（原文）：「端にあるクレーンゲームをクリックすると、クレーンゲームのミニゲームが始まるようにしてください。カプセルの中身は♠、♡、♦、♧が入ったバッチでログアウトまで名前の後ろに付きます。」

### 8.1 筐体と開き方

- 店の端のクレーンゲーム（`floor.json` の `decor` の `type: "crane"`）は**どれも遊べる**。番号は `decor` の中の並び順（1 から）。置き場所・台数は JSON で変えられる ✅。
- クリックの当たり判定は筐体と同じく箱の輪郭。吹き出し・小さな配信の枠の後、筐体と同じ段で見る（v0.1.0 で直した「上に重ねたものをクリックすると下の床へ歩く」を繰り返さない）。
- **遠くからクリックしたら、前のマスまで歩いてから自動で窓を開く** 🔧（筐体の窓の「前まで歩く」と同じ考え方。途中で床をクリックする・キーで歩くと取りやめ）。
  近い = 筐体と同じくチェビシェフ距離 2 マス以内。サーバも遊ぶたびに距離を確かめる（遠ければ `too-far`）。

### 8.2 ミニゲーム（窓の中の Canvas）

- ケースの中にカプセル（色違い 8 個）が転がっている。手前の左に出口。
- 本物のクレーンゲームと同じ 2 段階：［→］を**押している間だけ**アームが右へ → 離すと止まる → ［↑］（奥へ）を押している間だけ奥へ → 離すと止まる → ［下ろす］。
  どのボタンも 1 回だけ（離したら次の段階）。キーボードは → / ↑ / スペース。何もしないと 10 秒で次へ進む（［↑］待ちなら今の位置で下ろす）。床に影を出して狙いやすくする 🔧。
- ［下ろす］でサーバに結果を聞き、アームが下りる → つかむ → 持ち上げる → 出口へ運ぶ → 落とす → カプセルが開いてバッジ。途中で落ちることもある（「おしい！」）。
  演出は 1 回 10〜15 秒（動かす時間を含む）。効果音は短い合成音で、BGM の消音・音量に従う（お知らせのチャイムと同じ出口）。

### 8.3 当たり外れ（サーバが決める ✅）

- カプセルの配置（位置・色・中身）は**サーバのメモリ**が台ごとに持つ（店内の全員で同じケース）。中身はクライアントに送らない。
- クライアントは止めたアームの位置 (x, z)（ケースの床の 0〜1）だけを送る。サーバはいちばん近いカプセルとの距離 d から確率を決め、乱数で判定する。
  - **確率**：d ≤ 0.025 で最大（既定 **65%**、`CRANE_MAX_CHANCE`）、そこから d = 0.11 で 0 まで下がる（`(1 − t)^1.3`）。カプセルの半径は 0.075。
  - つかめなかったとき、カプセルに触れていれば半分は「持ち上げたが途中で落ちた」（カプセルは出口へ向かう途中に落ちて位置が変わる）、半分は「つかみ損ね」。触れていなければ「空振り」。
  - 取れたカプセルはケースから消え、新しいカプセルが 1 つ補充される。
  - 結果（取れた / 途中で落ちた / 空振り・カプセルの id・落ちた先・バッジ・新しい配置）を返し、クライアントはそのとおりに演出する。
- アームの位置を偽って送っても「ぴったり」以上にはならない（最大 65%）。
- **待ち時間**：1 回ごとに既定 **20 秒**（`CRANE_COOLDOWN_SEC`）。サーバが鍵ごとに確かめる（`cooldown`）。窓には残り秒数。

### 8.4 バッジ

- ♠ ♡ ♦ ♧ の 4 種類。取ったバッジは**名前の後ろ**に付く（例「たいよう♠♦」）。並びは ♠♡♦♧ に固定。名前の 20 文字とは別に数える。
  店内の頭上の名前・チャット（発言したときのバッジ）・上のバーの自分の名前・管理者の一覧・筐体の持ち主・ポスターの書いた人（いま店内にいればそのバッジ）に出す。
- **既定は「4 種類を 1 つずつ集める」**（`BADGE_MODE=unique`）：持っているものが出たら「もう持っています」（ダブりなし）。
  `BADGE_MODE=stack` で「同じものも重ねて持てる（各 `BADGE_STACK_MAX` 個まで、既定 3）」。
- 4 種類がそろったら（stack でも初めてそろったとき）窓に紙吹雪、チャットに「〇〇さんが 4 種類コンプリート！」。
- 取れたとき（新しいバッジが付いたときだけ）チャットに「〇〇さんがクレーンゲームで ♦ を取った！」。ダブり・外れは流さない。
- **ログアウトまで**：上のバーの［退店］で消える。接続が切れてから **30 分**（`BADGE_KEEP_MIN`）で消える。再読み込み・一時的な切断では残る。
  管理者に退室させられたときも消える。**サーバのメモリだけ**に持つ（再起動で消える。DB には書かない）🔧。

## 9. ポスター欄（v0.3.0、2026-10-25 ✅ ユーザー指定「ポスター欄には大会やイベント情報を書き込めるようにしてください」）

### 9.1 店内

- 左の壁（入口の奥側）に**掲示板**を描く（`floor.json` の `board`：`{ "wall": "left", "from": 6, "to": 12 }`。6 マス幅）。v0.2 までの飾りのポスター 2 枚の場所（前にあった植木は (0,7) → (0,5) へ動かした）。
- 貼られたポスターは掲示板に小さな紙として並ぶ（一覧の順に 4 枚まで。種類の色の帯・題名の頭の数文字・ピンで留めたものは赤いピン）。入りきらない分は「ほか n 枚」。
- 掲示板・紙をクリックすると一覧と詳細の窓（紙をクリックしたらその詳細）。遠くからでも開ける（読むだけなので）。

### 9.2 書くもの

| 項目 | 決まり |
|---|---|
| 題名 | 必須・40 文字まで |
| 種類 | 大会 / 参加型対戦 / イベント / そのほか |
| 開始の日時 | **必須** 🔧（並び順と自動ではがす時刻に使うため）。今から 30 日先まで |
| 終了の日時 | 任意。開始より後・開始から 7 日まで |
| ゲーム名 | 任意・30 文字まで |
| 内容 | 任意・400 文字まで（改行あり） |
| URL | 任意。**http(s) ならどのサイトでもよい** 🔧（大会の案内は start.gg・connpass・Discord・X・YouTube などさまざまなため）。300 文字まで・ユーザー名とパスワード入りの URL は不可。窓ではドメインを横に出し、新しいタブ（`noopener noreferrer`）で開く |

### 9.3 書ける人・守り

- 既定はプレイヤー全員（店内にいる人。`POSTER_WHO=admin` で管理者だけ）。
- 1 人が同時に貼れるのは **2 枚**（`POSTER_MAX_PER_USER`）。店全体で 40 枚まで。
- 回数制限：貼る・直すは鍵ごとに 10 分に 6 回、貼るのは IP ごとに 10 分に 10 回。
- **自動ではがす**：終了の日時、終了が無ければ開始から 1 日。終了は開始から 7 日までなので、どのポスターも開始から 7 日でなくなる。1 分ごとの掃除と、一覧を出す前に当てる。
- 書いた人は直せる・はがせる。管理者はどれでもはがせる・**ピンで固定**できる（一覧の先頭・壁でも先頭）。
- 一覧の順：ピンのもの → 開始の日時の近い順（始まっているものが先）→ 新しい順。
- 新しく貼られたら、チャットに「〇〇さんがポスターを貼りました：「題名」（日時）」、壁の大画面の流れる帯に「📅 近日のイベント」として流す（開始が 7 日以内のものを 3 件まで。お知らせと同じ帯）。
- SQLite に保存（再起動しても残る）。

## 11. スマホのレイアウト（v0.4.0、2026-10-25 ✅ ユーザー指定）

ユーザーの要望（原文）：「現在の表示はそのままで、スマホでアクセスした場合にはレイアウト変えて見やすくなるように出来ますか？」

### 11.1 切り替え ✅

- **PC の表示（§1 のフル HD 向け）は変えない**。PC で開いたときの見た目・操作は v0.3.0 と同じ（スクリーンショットで前後を比べる）。
- スマホのレイアウトにする条件：画面の幅が **900px 未満**、または `(pointer: coarse)`（指で操作する端末）で**短い辺が 600px 未満**（横向きの大きいスマホ 932×430 など）、
  または**スマホのブラウザ**（User-Agent Client Hints の mobile、無ければ User-Agent の iPhone・Android の Mobile など。タブレットは入れない）。
  → **スマホでは `?layout=pc` を付けない限り必ずスマホのレイアウト**（0.3.0 を公開中にスマホの人から「これ以上右にいけない」「横画面にするとチャットと被る」と声があった。0.3.0 は PC の表示のままだった）。
  画面を回したとき・ウィンドウの大きさを変えたときは自動で追従する（縦 = 高さ ≥ 幅、横 = 幅 > 高さ）。
- `?layout=pc` / `?layout=mobile` で強制できる（確認用。PC のブラウザでスマホのレイアウトを見る など）。
- 切り替えは `<html>` の class（`layout-mobile`・`orient-portrait` / `orient-landscape`）。スマホ用の CSS はすべて `.layout-mobile` の下に書き、PC の CSS は触らない。

### 11.2 縦向き（目安 390×844）

```
┌────────────────────────┐
│ V.ARCADE 👥7/50 📺3  ☰ │ ← 細いヘッダ（☰ = メニュー）
├────────────────────────┤
│                        │
│   店内の Canvas         │ ← 自分に追従して拡大（ピンチ・ドラッグ）
│   （画面いっぱい）       │   ［◎ 自分の所へ］（見回している間だけ）
│                        │
├────────────────────────┤
│ 👍 😂 😮 👏 ❤️ 👋 🎉 🔥 → │ ← エモーション（横スクロール）
│ たいよう：こんばんは！   │ ← チャットの最新 2〜3 行（タップ・上へのスワイプでシート）
│ [発言________] [送信]   │
└────────────────────────┘
```

- **メニュー**（☰ → 下からのシート）：自分の名前とバッジ・見た目を変える・BGM の操作（消音・音量・曲名と曲の一覧・次の曲）・
  「近くの配信を動画で出す」の切り替え・管理者・退店・操作の説明・版。
- **チャットのシート**：たたんだ状態は最新の 3 行だけ（読むだけ）。タップか上へのスワイプで下からのシート（画面の 6 割）、［全画面］で全体。
  シートの中は PC の欄と同じ（履歴・発言・自分の発言の 📌・管理者の ×。スマホではホバーが無いので 📌 と × は常に出す）。下へのスワイプか［閉じる］でたたむ。

### 11.3 横向き（目安 844×390）

- 店内を左に大きく、右に幅 300px の細い欄（上にヘッダ、その下にエモーション、残りにチャットの履歴と発言欄）。
  横向きは高さが無く、シートにすると開くたびに店内が隠れるので、右の欄に出しっぱなしにした 🔧。欄は店内に重ならない（店内の Canvas の横に並ぶ）。
- 右の欄の上の［›］で**たたむ**と、欄は幅 56px の帯（［💬］で開く・［☰］）だけになり、店内が広くなる。たたんだかどうかは localStorage `va:mobile` に残す。

### 11.4 店内の Canvas（スマホ）

- **カメラ**：自分のキャラクターに追従する（なめらかに追う）。既定の倍率は「店全体が入る倍率」の **2.4 倍**（縦向きで店の幅の約 4 割・横向きで高さの約半分が見える）🔧。
  - **2 本指のピンチ**で拡大・縮小（店全体が入る倍率 〜 その 5 倍・最大 2.2）。指の間の点を中心に拡大する。倍率は見回しが終わっても残る。
  - **1 本指のドラッグ**で見回す。指を離して **3 秒**たつと自分の所へ戻る（なめらかに）。見回している間は右上に［◎ 自分の所へ］のボタン。
  - 店の外が大きく見えないよう、カメラの中心は店の範囲に収める（画面より店が小さい向きは真ん中）。ただし**店の端の外まで少し動かせる**
    （横は画面の幅の 18%、縦は高さの 30%）。端のマスを画面の内側（下端の宣伝の吹き出し・右上のボタンの無い所）まで寄せてタップできるように。
  - マウスのホイール（`?layout=mobile` を PC で見るとき）でも拡大・縮小。
- **長押し**：指を動かさずに **0.45 秒**で、指の下の床のマスへ歩く（筐体・クレーンゲームの当たり判定を見ない）。筐体の箱は高いので、
  その奥の床は画面の上で箱と重なり、タップでは筐体が開く（PC はキーボードで行ける）。スマホでもそこへ行けるように 🔧。
- 指を離したあとにブラウザが合成する click は止める（`touchend` で preventDefault）。タップで開いた窓の背景にその click が届いて、開いた窓がすぐ閉じてしまうため。
- **タップとドラッグの区別**：指が触れてから離すまでに動いた距離が **10px 以下**で、2 本目の指が触れていなければタップ。タップは今の当たり判定（pick）をそのまま使う
  （床 = 歩く・筐体・クレーンゲーム・掲示板・大画面・宣伝の吹き出し・小さな配信の枠）。
- **文字の大きさ**：頭上の名前・吹き出し・エモーション・筐体の札・宣伝の吹き出しは、拡大率ではなく「文字の倍率」（拡大率を 1.0〜1.4 に収めたもの）で描く。縮小しても文字は小さくなりすぎない。
- **宣伝の吹き出し**：画面の**下端の中央**に出す（筐体の横に出すと画面からはみ出し、上に出すと筐体の上の小さな配信の枠と重なるため）。筐体へ点線を引く。タップでその筐体の窓。
- **近くの筐体の小さな配信**：既定は**動画を出さず、サムネイルの枠**（同じ場所・「▶ タップで視聴」）。メニューの「近くの配信を動画で出す」で PC と同じ動画にできる（localStorage `va:mobile`）。
- 床・壁は店全体の大きな canvas に 1 回だけ描き、毎フレームはずらして貼る（倍率が変わったら描き直す。ピンチの間は拡大して貼り、止まってから描き直す）。
- キーボード（WASD・矢印キー）は PC のまま残る。スマホに仮想のスティックは付けない（タップで歩く）。

### 11.5 窓（スマホ）

- 筐体・管理者・大画面の一覧・ポスター・クレーンゲーム・見た目の変更は**画面の下からのシート（全幅）**。ポスターと見た目の変更は全画面。ボタンは高さ 44px 以上。
- **クレーンゲーム**：ミニゲームの Canvas を画面の幅に合わせて縮める。ボタンは今までどおり押している間だけ動く（pointerdown / pointerup。長押しのメニューは出さない）。
- **ポスター**：一覧の下に詳細（1 列）。書く・直すときは一覧を隠してフォームだけ。
- **視聴画面**：縦向きは動画を画面の幅いっぱい（16:9）にし、その下に宣伝・［YouTube で開く］・チャット。横向きは動画を左に、右の欄に宣伝とチャット。
- **入店の画面**：見本の人形と入力欄を縦に並べる。

### 11.6 スマホのブラウザ

- 高さは `100dvh`（アドレスバーの出入りで変わる）。`viewport-fit=cover` と `env(safe-area-inset-*)` でノッチ・下のバーを避ける。
  Android Chrome はキーボードが出たときに画面を縮める（`interactive-widget=resizes-content`）。
- 入力欄の文字は 16px 以上（iOS がフォーカスで拡大しないように）。
- 店内の Canvas は `touch-action: none`（ダブルタップの拡大・ページのピンチ拡大・スクロールを止める）。ボタンは `touch-action: manipulation`。

## 12. コミュニケーションノート（v0.4.0、2026-10-25 ✅ ユーザー指定）

ユーザーの要望（原文）：「3行くらいの文章と名前が書ける　コミュニケーションノートを置いてください。見開きで表示されます。ページをめくっていけます。それと機能追加要望箱を設けてください。」
決定 ✅：ノートは誰でも読める。要望は管理者だけが読める。

### 12.1 店内

- 入口の近くの**机の上にノート**（`floor.json` の `decor` の `type: "note"`。通れないマス）。クリック（タップ）で開く。遠ければ机の前まで歩いてから開く（クレーンゲームと同じ仕組み。近い = 2 マス以内）。
  カーソルを置くと札「コミュニケーションノート　クリックで開く」。

### 12.2 表示とめくり方

- **PC**：左右 2 ページの本の形（見開き）。**スマホ**：縦向きは 1 ページずつ、横向きは見開き。
- 1 ページに **4 件**。古い順に 1 ページ目から並べ、**開いたときはいちばん新しいページ（見開き）**を出す。
- めくる：［‹］［›］・キーボードの ← →・スマホは左右のスワイプ。紙をめくる短いアニメーション（0.35 秒）。最初と最後のページで止まる。何ページ目か（例「5–6 / 12」）。
- 1 件：名前・文章（3 行まで）・書いた日時（月/日 時:分）。罫線の上に書いた見た目（教科書体など手書きに近い字が端末にあればそれ、無ければふつうの字。読みやすさ優先）。
- 新しく書かれたら、開いている人のノートにもその場で加わる（今のページは動かさない。ページ数が増える）。消されたら消える。

### 12.3 書く

- ［✎ 書く］で書く欄を出す（PC は本の下、スマホは本の代わり）。書いたらいちばん新しいページへ。
- **名前**：既定は自分の店内の名前。書き換えてよい（1〜20 文字・NG 語）。**文章**：1〜**90 文字**・**3 行まで**（改行は 2 回まで。空の行は詰める）・NG 語。
- 書けるのは店内にいる人（入室を止められていない人）。

### 12.4 守り・保存

- 回数制限：鍵ごとに **10 分に 3 件**・IP ごとに 10 分に 10 件（形の検証の後に数える）。
- 書いた人は自分の分を消せる（鍵で確かめる）。管理者はどれでも消せる。ほかの人は消せない（403）。
- SQLite に保存（再起動しても残る）。**2000 件**まで（超えたら古いものから消す）。
- 読むのは誰でも（API は鍵なしでも読める）。一覧は新しいものから 120 件ずつ読み、古いページへめくったら続きを読む。
- チャットへの案内：「📖 〇〇 さんがノートに書きました」を**同じ人は 30 分に 1 回まで**流す（控えめに）🔧。

## 13. 機能追加要望箱（v0.4.0、2026-10-25 ✅ ユーザー指定）
