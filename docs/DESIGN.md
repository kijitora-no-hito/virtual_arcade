# バーチャルゲームセンター 設計メモ（v0.5.1, 2026-10-26。Q1〜Q7 決定、§7 店内の BGM は v0.2.0、§8 クレーンゲーム・§9 ポスター欄・§10 チャットのピン止めは v0.3.0、§11 スマホのレイアウト・§12 コミュニケーションノート・§13 機能追加要望箱は v0.4.0、§14 オープン部屋と予約部屋は v0.5.0、§15 PC の上のバー・チャットの残す時間は v0.5.1）

Web ブラウザから入れる、クオータービューのバーチャルなゲームセンター。参加者は自分のキャラクターを歩かせ、チャットとエモーションでやりとりする。
ゲームの筐体には YouTube の配信 URL と宣伝（イベント名・ゲーム名・プレイヤー名・備考）を設定でき、どこで何が配信されているかが店内を歩いて分かる。
**Android アプリではなく Web アプリ**。仮の名前・フォルダ名は `virtual_arcade`。

> ✅ = ユーザー指定、🔧 = 叩き台の案（要確認は末尾の表）

---

## 1. 画面（PC・フル HD 1920×1080 向け ✅）

```
┌──────────────────────────────────────────────┬──────────────┐
│  クオータービューの店内（キャラクター・筐体・壁の大画面）     │  チャット      │
│                                              │  （発言・案内） │
│   ┌壁の大画面: 配信一覧┐                        │              │
│   └─────────────────┘                        │              │
│    [筐体][筐体][筐体]   ← 画面に配信中の印・サムネイル │              │
│        🙂 ← 自分        😀 ほかの人（頭上に名前・吹き出し）│              │
├──────────────────────────────────────────────┤              │
│ エモーション [👍][😂][😮][👏][❤]  移動: クリック / WASD    │ [発言欄]      │
└──────────────────────────────────────────────┴──────────────┘
```

- **入室**：名前（20 文字まで）とキャラクターの見た目（色・帽子など数種）を選ぶだけ 🔧。アカウント登録なし（ブラウザに保存した鍵で同じ人と見分ける）。
- **移動** ✅：床をクリックした所へ歩く（経路探索）＋ WASD / 矢印キー 🔧。ほかの人の動きもリアルタイムに見える（WebSocket）。
- **チャット** ✅：店内全体に届く。右の欄に流れ、**発言した人の頭上に吹き出し**（数秒。続けて発言したら差し替え。長い文は吹き出しでは省略）。
- **エモーション** ✅：ボタンで頭上に大きな絵文字・動き（手を振る・拍手など）。

## 2. 筐体

- 店内に筐体を並べる（🔧 初期は 12〜20 台。並びは店のレイアウトのデータで決める）。
- **設定できるもの** ✅：
  - YouTube の配信 URL（`youtube.com/watch?v=…`・`youtu.be/…`・`youtube.com/live/…` だけ受け付ける）
  - 宣伝：イベント名（参加型対戦・大会など）、ゲーム名、プレイヤー名、備考
- **誰が設定できるか** ✅：管理者とプレイヤー。🔧 案：空いている筐体を「使う」と、その人が持ち主になって設定できる。持ち主が外す・時間切れ（例 6 時間更新なし）で空きに戻る。管理者はどの筐体も変更・解除できる。
- **店内での見え方** ✅：簡易表現で「配信している」ことが分かる。
  - 🔧 筐体の画面に YouTube のサムネイル画像（`i.ytimg.com` の静止画。API キー不要）を貼り、「LIVE」の札と光の点滅。頭上に宣伝の短い札（イベント名・ゲーム名）。
  - 🔧 筐体に近づく / カーソルを置くと、宣伝の全文（イベント名・ゲーム名・プレイヤー名・備考）の吹き出し。
- **筐体の画面に配信そのものを映す**（希望・難しければ見送り）：
  - 🔧 技術的には、筐体の画面の位置に小さな YouTube の埋め込み（iframe）を重ねれば映せる。ただし同時に何本も再生すると重く、音・自動再生の制限もある。
  - 🔧 案：ふだんはサムネイル、自分が近くにいる筐体 1 台だけ小さく埋め込み再生（音なし）にする。
- **筐体にアクセス** ✅：筐体をクリック → 「この中で視聴する（視聴画面）」か「YouTube で開く（新しいタブ）」を選ぶ。
  - 視聴画面 🔧：大きな埋め込みプレイヤー＋宣伝＋その場のチャット（店内のチャットと同じ欄）。［店内に戻る］。視聴中も店内では自分のキャラクターが筐体の前に座っている。

## 3. 壁の大画面 ✅

- 店の壁に大きな液晶画面。**いま配信中の筐体の一覧**（サムネイル・イベント名・ゲーム名・プレイヤー名）を順に表示（🔧 数秒ごとに切り替え、または一覧表）。
- 🔧 クリックすると一覧の拡大表示 → 選んだ筐体へ歩いて行く / そのまま視聴画面。
- 🔧 管理者のお知らせ（大会の予定など）も流せる。

## 4. 管理者

- 🔧 管理者の合言葉（サーバの設定）で管理者になる。できること：筐体の設定・解除、お知らせ、チャットの発言の削除、人を退室させる・入室を止める。

## 6. 公開するときの注意（🔧）

- 誰でも入れるチャットになるので、NG 語・回数制限・管理者の削除と退室は最初から入れる。
- 筐体に設定できるのは YouTube の URL だけ（ほかのサイトへの誘導にしない）。宣伝の文字にも NG 語。
- YouTube の埋め込みは YouTube の利用規約に従う（埋め込みが無効な配信は「YouTube で開く」だけ）。

## 7. 店内の BGM（v0.2.0、2026-10-25 ✅ ユーザー指定「店内に BGM を流しましょうか」）

経緯：近くの筐体の小さな配信に音を出す案はやめた（✅）。小さな配信は今までどおり**音なし**で、BGM とは関係しない。

### 7.1 曲 ✅

- **同梱の曲（既定）**：魔王魂のアコースティック 5 曲（`アコースティック02 / 11 / 46 / 50 / 52`。曲名は魔王魂のサイトの表記）。✅ ユーザーが `bgm/` に mp3 を置いた。
  店内ではこの 5 曲を**順番に**流す（1 曲 = イントロ + 本体 2 周。🔧 叩き台）。
- **合成の曲**：権利の心配がないよう、Web Audio API でブラウザの中で合成して演奏するオリジナル 3 曲（チップチューン。矩形波 25% / 12.5% / 50%・三角波・ノイズのドラム）。
  一覧から選べる（選んだ曲をくり返す）。曲はデータ（`shared/src/songs.ts`。音符の並び・テンポ・音色）で、足すときは同じ形で書いて `npm test` で検証する（`shared/src/bgm.ts` の先頭に書き方）。
  | 曲名 | 雰囲気 | テンポ・長さ |
  |---|---|---|
  | ネオン・スタート | 明るい店内のメイン（C メジャー、25% 矩形波のメロディ・三角波のオクターブのベース・12.5% のアルペジオ） | 136 BPM・24 小節（約 42 秒） |
  | ミッドナイト・ロビー | 落ち着いた夜の店内（A マイナーのセブンスの和音・三角波のパッド・こだまのかかったメロディ） | 92 BPM・16 小節（約 42 秒） |
  | トーナメント・ファイア | 大会の盛り上がり（E マイナー、16 分で刻むベースとハイハット） | 152 BPM・24 小節（約 38 秒） |
- **自分の曲への差し替え**（任意）：サーバの `data/bgm/`（環境変数 `BGM_DIR`）に音声ファイル（mp3 / ogg / m4a）を置けば一覧に加わる。曲名・作者は `data/bgm/bgm.json`。
  ファイルの権利は置く人の責任（`data/bgm/README.md`）。

### 7.2 ループ（同梱の曲 ✅）

- `tools/bgm/loop_bgm.py`がループ点 A〜B を自動で探し（`tools/bgm/loops.json`。git には入れない）、
  イントロ（頭〜A）と本体（A〜B。末尾で B の手前と A の手前を短く重ねて、最後のサンプルの次が先頭へ連続につながる）の Ogg Vorbis を `data/bgm/` に書く。
- `tools/bgm/loudness.py --target -17 --apply` で 5 曲の音量（統合ラウドネス）を −17 LUFS 前後にそろえ、`bgm.json` の `gain` に書く。合成の曲も −17 LUFS 前後になるよう曲ごとの `gain` を付けた。
- ブラウザは Web Audio で、イントロのバッファ → 本体のバッファ（`AudioBufferSourceNode.loop = true`、`loopEnd` = 本体の長さ）をサンプル単位でつなぐ。
  `<audio loop>` は継ぎ目にすき間が出るので使わない。
- ブラウザ（Chrome の decodeAudioData）が短い Vorbis の末尾を削ることがあった（0.15 秒のイントロで 87 サンプル）ので、ogg の後ろには続きの音を 0.25 秒足し、
  正しい長さを `bgm.json` の `introSec` / `bodySec` に書いてその長さで鳴らす。
- デコード済みのバッファは今の曲と次の曲の分だけ持つ（次の曲は切り替えの 25 秒前から読み込む）。曲の切り替えは 0.6 秒のフェード。

### 7.3 再生

- **自動再生の制限**：入店のボタンを押した操作の中で AudioContext を作る。再読み込みで自動入店した場合は最初のクリック・キー入力で始める。それまでは下のバーに「🔇 クリックで BGM」。
- **操作**（下のバーのエモーションの左）：［🔈/🔇］・音量のスライダー（既定 25%）・曲名とクレジット（クリックで曲の一覧）・［次の曲］。
  設定（音量・消音・曲）は localStorage `va:bgm`。
- **視聴画面の動画** ✅：大きな埋め込みで動画が**実際に再生を始めた瞬間**に、BGM を 1.8 秒でフェードアウトして止める。視聴画面を閉じて店内に戻ったら 1.5 秒でフェードインして続きから。
  動画の一時停止・終了だけ（視聴画面は開いたまま）では戻さない。
  - 検出：埋め込みの URL に `enablejsapi=1&origin=<このページのオリジン>` を付け、埋め込みへ `{"event":"listening"}` を送って、
    返ってくる状態（`onStateChange` / `infoDelivery` の 1 = 再生中）を `message` で受ける。送り元の窓（この埋め込み）とオリジン（youtube-nocookie.com / youtube.com）を確かめる。
  - 予備：状態が 1 度も届かなければ、視聴画面を開いて 5 秒で止める（状態が届いているのに再生していない = 自動再生が止められた ときは止めない）。
  - 判断は純粋な関数（`client/src/audio/videoDuck.ts`、テストあり）。
- **お知らせのチャイム**：管理者のお知らせが増えたら短いチャイム（3 音）を BGM とは別に鳴らす。消音の設定に従う。
- タブが裏に回っても鳴り続ける。合成の曲は先読みのスケジューラ（見えているときは 0.3 秒先、裏では 1.5 秒先まで予約）で、タイマーの揺れに強い。

### 7.4 曲名・クレジット・規約

- 合成の曲は「オリジナル（このアプリのために作曲）」。同梱の曲は「**音楽：魔王魂（ループ・音量の調整のため編集）**」を BGM の操作の曲名の下・曲の一覧・入店の画面に出す。
- 魔王魂の規約（https://maou.audio/rule/ ）：クレジット表記必須・改変したらその旨を記載（ループのための切り出し・つなぎ目の重ね・
  再エンコード・音量の調整をしたので「ループ・音量の調整のため編集」）・**曲単体の再配布は禁止**（曲のファイルを単体で落とせる一覧ページは作らず、BGM として流すだけ。
  元の mp3 も加工した ogg も公開リポジトリに入れない。`npm run package` の tar には加工した ogg と一覧だけを入れる）。

## 8. クレーンゲーム（v0.3.0、2026-10-25 ✅ ユーザー指定）

ユーザーの要望（原文）：「端にあるクレーンゲームをクリックすると、クレーンゲームのミニゲームが始まるようにしてください。カプセルの中身は♠、♡、♦、♧が入ったバッチでログアウトまで名前の後ろに付きます。」

### 8.1 筐体と開き方

- 店の端のクレーンゲーム（`floor.json` の `decor` の `type: "crane"`）は**どれも遊べる**。番号は `decor` の中の並び順（1 から）。置き場所・台数は JSON で変えられる ✅。
- クリックの当たり判定は筐体と同じく箱の輪郭。吹き出し・小さな配信の枠の後、筐体と同じ段で見る（v0.1.0 で直した「上に重ねたものをクリックすると下の床へ歩く」を繰り返さない）。
- **遠くからクリックしたら、前のマスまで歩いてから自動で窓を開く** 🔧（筐体の窓の「前まで歩く」と同じ考え方。途中で床をクリックする・キーで歩くと取りやめ）。
  近い = 筐体と同じくチェビシェフ距離 2 マス以内。サーバも遊ぶたびに距離を確かめる（遠ければ `too-far`）。

### 8.2 ミニゲーム（窓の中の Canvas）

- ケースの中にカプセル（色違い 8 個）が転がっている。手前の左に出口。
- 本物のクレーンゲームと同じ 2 段階：［→］を**押している間だけ**アームが右へ → 離すと止まる → ［↑］（奥へ）を押している間だけ奥へ → 離すと止まる → ［下ろす］。
  どのボタンも 1 回だけ（離したら次の段階）。キーボードは → / ↑ / スペース。何もしないと 10 秒で次へ進む（［↑］待ちなら今の位置で下ろす）。床に影を出して狙いやすくする 🔧。
- ［下ろす］でサーバに結果を聞き、アームが下りる → つかむ → 持ち上げる → 出口へ運ぶ → 落とす → カプセルが開いてバッジ。途中で落ちることもある（「おしい！」）。
  演出は 1 回 10〜15 秒（動かす時間を含む）。効果音は短い合成音で、BGM の消音・音量に従う（お知らせのチャイムと同じ出口）。

### 8.3 当たり外れ（サーバが決める ✅）

- カプセルの配置（位置・色・中身）は**サーバのメモリ**が台ごとに持つ（店内の全員で同じケース）。中身はクライアントに送らない。
- クライアントは止めたアームの位置 (x, z)（ケースの床の 0〜1）だけを送る。サーバはいちばん近いカプセルとの距離 d から確率を決め、乱数で判定する。
  - **確率**：d ≤ 0.025 で最大（既定 **65%**、`CRANE_MAX_CHANCE`）、そこから d = 0.11 で 0 まで下がる（`(1 − t)^1.3`）。カプセルの半径は 0.075。
  - つかめなかったとき、カプセルに触れていれば半分は「持ち上げたが途中で落ちた」（カプセルは出口へ向かう途中に落ちて位置が変わる）、半分は「つかみ損ね」。触れていなければ「空振り」。
  - 取れたカプセルはケースから消え、新しいカプセルが 1 つ補充される。
  - 結果（取れた / 途中で落ちた / 空振り・カプセルの id・落ちた先・バッジ・新しい配置）を返し、クライアントはそのとおりに演出する。
- アームの位置を偽って送っても「ぴったり」以上にはならない（最大 65%）。
- **待ち時間**：1 回ごとに既定 **20 秒**（`CRANE_COOLDOWN_SEC`）。サーバが鍵ごとに確かめる（`cooldown`）。窓には残り秒数。

### 8.4 バッジ

- ♠ ♡ ♦ ♧ の 4 種類。取ったバッジは**名前の後ろ**に付く（例「たいよう♠♦」）。並びは ♠♡♦♧ に固定。名前の 20 文字とは別に数える。
  店内の頭上の名前・チャット（発言したときのバッジ）・上のバーの自分の名前・管理者の一覧・筐体の持ち主・ポスターの書いた人（いま店内にいればそのバッジ）に出す。
- **既定は「4 種類を 1 つずつ集める」**（`BADGE_MODE=unique`）：持っているものが出たら「もう持っています」（ダブりなし）。
  `BADGE_MODE=stack` で「同じものも重ねて持てる（各 `BADGE_STACK_MAX` 個まで、既定 3）」。
- 4 種類がそろったら（stack でも初めてそろったとき）窓に紙吹雪、チャットに「〇〇さんが 4 種類コンプリート！」。
- 取れたとき（新しいバッジが付いたときだけ）チャットに「〇〇さんがクレーンゲームで ♦ を取った！」。ダブり・外れは流さない。
- **ログアウトまで**：上のバーの［退店］で消える。接続が切れてから **30 分**（`BADGE_KEEP_MIN`）で消える。再読み込み・一時的な切断では残る。
  管理者に退室させられたときも消える。**サーバのメモリだけ**に持つ（再起動で消える。DB には書かない）🔧。

## 9. ポスター欄（v0.3.0、2026-10-25 ✅ ユーザー指定「ポスター欄には大会やイベント情報を書き込めるようにしてください」）

### 9.1 店内

- 左の壁（入口の奥側）に**掲示板**を描く（`floor.json` の `board`：`{ "wall": "left", "from": 6, "to": 12 }`。6 マス幅）。v0.2 までの飾りのポスター 2 枚の場所（前にあった植木は (0,7) → (0,5) へ動かした）。
- 貼られたポスターは掲示板に小さな紙として並ぶ（一覧の順に 4 枚まで。種類の色の帯・題名の頭の数文字・ピンで留めたものは赤いピン）。入りきらない分は「ほか n 枚」。

## 11. スマホのレイアウト（v0.4.0、2026-10-25 ✅ ユーザー指定）

ユーザーの要望（原文）：「現在の表示はそのままで、スマホでアクセスした場合にはレイアウト変えて見やすくなるように出来ますか？」

### 11.1 切り替え ✅

- **PC の表示（§1 のフル HD 向け）は変えない**。PC で開いたときの見た目・操作は v0.3.0 と同じ（スクリーンショットで前後を比べる）。
- スマホのレイアウトにする条件：画面の幅が **900px 未満**、または `(pointer: coarse)`（指で操作する端末）で**短い辺が 600px 未満**（横向きの大きいスマホ 932×430 など）、
  または**スマホのブラウザ**（User-Agent Client Hints の mobile、無ければ User-Agent の iPhone・Android の Mobile など。タブレットは入れない）。
  → **スマホでは `?layout=pc` を付けない限り必ずスマホのレイアウト**（0.3.0 を公開中にスマホの人から「これ以上右にいけない」「横画面にするとチャットと被る」と声があった。0.3.0 は PC の表示のままだった）。
  画面を回したとき・ウィンドウの大きさを変えたときは自動で追従する（縦 = 高さ ≥ 幅、横 = 幅 > 高さ）。
- `?layout=pc` / `?layout=mobile` で強制できる（確認用。PC のブラウザでスマホのレイアウトを見る など）。
- 切り替えは `<html>` の class（`layout-mobile`・`orient-portrait` / `orient-landscape`）。スマホ用の CSS はすべて `.layout-mobile` の下に書き、PC の CSS は触らない。

### 11.2 縦向き（目安 390×844）

```
┌────────────────────────┐
│ V.ARCADE 👥7/50 📺3  ☰ │ ← 細いヘッダ（☰ = メニュー）
├────────────────────────┤
│                        │
│   店内の Canvas         │ ← 自分に追従して拡大（ピンチ・ドラッグ）
│   （画面いっぱい）       │   ［◎ 自分の所へ］（見回している間だけ）
│                        │
├────────────────────────┤
│ 👍 😂 😮 👏 ❤️ 👋 🎉 🔥 → │ ← エモーション（横スクロール）
│ たいよう：こんばんは！   │ ← チャットの最新 2〜3 行（タップ・上へのスワイプでシート）
│ [発言________] [送信]   │
└────────────────────────┘
```

- **メニュー**（☰ → 下からのシート）：自分の名前とバッジ・見た目を変える・BGM の操作（消音・音量・曲名と曲の一覧・次の曲）・
  「近くの配信を動画で出す」の切り替え・管理者・退店・操作の説明・版。
- **チャットのシート**：たたんだ状態は最新の 3 行だけ（読むだけ）。タップか上へのスワイプで下からのシート（画面の 6 割）、［全画面］で全体。
  シートの中は PC の欄と同じ（履歴・発言・自分の発言の 📌・管理者の ×。スマホではホバーが無いので 📌 と × は常に出す）。下へのスワイプか［閉じる］でたたむ。

### 11.3 横向き（目安 844×390）

- 店内を左に大きく、右に幅 300px の細い欄（上にヘッダ、その下にエモーション、残りにチャットの履歴と発言欄）。
  横向きは高さが無く、シートにすると開くたびに店内が隠れるので、右の欄に出しっぱなしにした 🔧。欄は店内に重ならない（店内の Canvas の横に並ぶ）。
- 右の欄の上の［›］で**たたむ**と、欄は幅 56px の帯（［💬］で開く・［☰］）だけになり、店内が広くなる。たたんだかどうかは localStorage `va:mobile` に残す。

### 11.4 店内の Canvas（スマホ）

- **カメラ**：自分のキャラクターに追従する（なめらかに追う）。既定の倍率は「店全体が入る倍率」の **2.4 倍**（縦向きで店の幅の約 4 割・横向きで高さの約半分が見える）🔧。
  - **2 本指のピンチ**で拡大・縮小（店全体が入る倍率 〜 その 5 倍・最大 2.2）。指の間の点を中心に拡大する。倍率は見回しが終わっても残る。
  - **1 本指のドラッグ**で見回す。指を離して **3 秒**たつと自分の所へ戻る（なめらかに）。見回している間は右上に［◎ 自分の所へ］のボタン。
  - 店の外が大きく見えないよう、カメラの中心は店の範囲に収める（画面より店が小さい向きは真ん中）。ただし**店の端の外まで少し動かせる**
    （横は画面の幅の 18%、縦は高さの 30%）。端のマスを画面の内側（下端の宣伝の吹き出し・右上のボタンの無い所）まで寄せてタップできるように。
  - マウスのホイール（`?layout=mobile` を PC で見るとき）でも拡大・縮小。
- **長押し**：指を動かさずに **0.45 秒**で、指の下の床のマスへ歩く（筐体・クレーンゲームの当たり判定を見ない）。筐体の箱は高いので、
  その奥の床は画面の上で箱と重なり、タップでは筐体が開く（PC はキーボードで行ける）。スマホでもそこへ行けるように 🔧。
- 指を離したあとにブラウザが合成する click は止める（`touchend` で preventDefault）。タップで開いた窓の背景にその click が届いて、開いた窓がすぐ閉じてしまうため。
- **タップとドラッグの区別**：指が触れてから離すまでに動いた距離が **10px 以下**で、2 本目の指が触れていなければタップ。タップは今の当たり判定（pick）をそのまま使う
  （床 = 歩く・筐体・クレーンゲーム・掲示板・大画面・宣伝の吹き出し・小さな配信の枠）。
- **文字の大きさ**：頭上の名前・吹き出し・エモーション・筐体の札・宣伝の吹き出しは、拡大率ではなく「文字の倍率」（拡大率を 1.0〜1.4 に収めたもの）で描く。縮小しても文字は小さくなりすぎない。
- **宣伝の吹き出し**：画面の**下端の中央**に出す（筐体の横に出すと画面からはみ出し、上に出すと筐体の上の小さな配信の枠と重なるため）。筐体へ点線を引く。タップでその筐体の窓。
- **近くの筐体の小さな配信**：既定は**動画を出さず、サムネイルの枠**（同じ場所・「▶ タップで視聴」）。メニューの「近くの配信を動画で出す」で PC と同じ動画にできる（localStorage `va:mobile`）。
- 床・壁は店全体の大きな canvas に 1 回だけ描き、毎フレームはずらして貼る（倍率が変わったら描き直す。ピンチの間は拡大して貼り、止まってから描き直す）。
- キーボード（WASD・矢印キー）は PC のまま残る。スマホに仮想のスティックは付けない（タップで歩く）。

### 11.5 窓（スマホ）

- 筐体・管理者・大画面の一覧・ポスター・クレーンゲーム・見た目の変更は**画面の下からのシート（全幅）**。ポスターと見た目の変更は全画面。ボタンは高さ 44px 以上。
- **クレーンゲーム**：ミニゲームの Canvas を画面の幅に合わせて縮める。ボタンは今までどおり押している間だけ動く（pointerdown / pointerup。長押しのメニューは出さない）。
- **ポスター**：一覧の下に詳細（1 列）。書く・直すときは一覧を隠してフォームだけ。
- **視聴画面**：縦向きは動画を画面の幅いっぱい（16:9）にし、その下に宣伝・［YouTube で開く］・チャット。横向きは動画を左に、右の欄に宣伝とチャット。
- **入店の画面**：見本の人形と入力欄を縦に並べる。

### 11.6 スマホのブラウザ

- 高さは `100dvh`（アドレスバーの出入りで変わる）。`viewport-fit=cover` と `env(safe-area-inset-*)` でノッチ・下のバーを避ける。
  Android Chrome はキーボードが出たときに画面を縮める（`interactive-widget=resizes-content`）。
- 入力欄の文字は 16px 以上（iOS がフォーカスで拡大しないように）。
- 店内の Canvas は `touch-action: none`（ダブルタップの拡大・ページのピンチ拡大・スクロールを止める）。ボタンは `touch-action: manipulation`。

## 12. コミュニケーションノート（v0.4.0、2026-10-25 ✅ ユーザー指定）

部屋名は予約部屋の中にも出す・予約した人（主催）は予約部屋の管理者（§14.6）・予約部屋に時計と残り時間（§14.7）・入店の画面から予約表を開いて予約し、合言葉でそのまま予約部屋に入れる・オープン部屋に予約部屋の扉と、予約カレンダー（物）を置く。

### 14.1 部屋

- 今までの店が **オープン部屋**（動きは変えない）。**予約部屋**を 1 つ足す。レイアウトは同じ（`floor.json` を共有）で、色を変えて見分ける（琥珀と青緑・左の壁の看板「RESERVED ROOM 予約部屋（貸し切り）」）🔧。
- **部屋ごと**：店内の人・チャット（ピン止め・吹き出しを含む）・エモーション・筐体（配信・宣伝）・壁の大画面・お知らせの帯・クレーンゲーム（ケースと待ち時間）・人数の上限（それぞれ `MAX_PLAYERS`）。
- **店全体で 1 つ**：コミュニケーションノート・要望箱・ポスター（掲示板）・BGM の選択・クレーンゲームのバッジ（退店まで。部屋を移っても付いたまま）。
  ポスターを貼った・ノートに書いたというチャットの案内は、書いた人のいる部屋に流す。
- 部屋を移っても名前・見た目・バッジはそのまま。ピン止めの吹き出しは部屋ごとのチャットなので外れる 🔧。移った先では扉の前のマスに立つ。

### 14.2 予約

| 項目 | 決まり |
|---|---|
| 枠 | **30 分単位**（00 分・30 分に始まる）。長さ 30 分〜5 時間。今の 30 分の枠から **14 日先**まで。時刻はすべて**日本時間**（JST）で出す |
| 1 人の上限 | **これからの予約と使っている最中の予約の長さの合計が 5 時間まで**（鍵ごと）✅。予約の形に「あなたが予約できる残り」を出す |
| 重なり | ほかの予約と重なる時間は取れない（終わりと次の始まりが同じ時刻はよい） |
| 部屋名 | 必須・30 文字まで・NG 語（予約表と予約部屋の中に出る）✅ |
| 予約する人の名前 | 必須・20 文字まで（既定は店内の名前）・NG 語 ✅ 予約表に出す |
| 説明 | 任意・120 文字まで・NG 語 |
| 合言葉 | 4〜32 文字。サーバは **scrypt の塩つきハッシュだけ**を持つ（クライアントにはハッシュも送らない）。参加する人には予約した人が伝える |
| 予約できる人 | 入店したことのある鍵（名前を決めた人）。入店の画面からも予約できる（予約する前に名前を決める） |
| 取り消し | 予約した人・管理者（管理者の窓の「🔑 予約」タブ）。使っている最中に取り消したら予約部屋はすぐ閉まる |
| 回数制限 | 予約は鍵ごと 1 時間に 6 回・IP ごと 12 回（形の検証の後に数える）🔧 |
| 保存 | SQLite の**新しい表 `reservations` だけ**（ほかの表は変えない）。終わってから 30 日・2000 行を超えた古い行は消す |

- **予約表**（誰でも見られる。合言葉は出さない）：上に「いま開いています「部屋名」（予約：名前）〜21:00［🔑 予約部屋に入る］」か「現在予約はありません。次は ○○」。
  - **カレンダー**：PC は 7 日 × 30 分の表（‹ 前の 7 日・次の 7 日 ›。開くと今の時刻のあたり）。スマホは日を選ぶボタン（今日・明日・日付、予約の数）とその日の 30 分の枠の一覧 ✅。
    予約はブロック（部屋名・時刻・予約した人）。**空いている枠を押すと予約の形**（開始はその枠。同じ日の空いている時刻と、重ならない長さから選べる）。
  - **一覧**：これからの予約を開始の順に（開室中・あなたの予約の印・取り消す）。
- 予約したらオープン部屋のチャットに「📅 〇〇 さんが予約部屋を予約しました：「部屋名」（日時）」🔧。

### 14.3 入る

- **オープン部屋の物**（`floor.json` の decor）✅：奥の右の壁ぎわに**予約部屋の扉**（`door`。(2, 0)）と、その横に**予約カレンダー**（`calendar`。(4, 0)。脚の付いたカレンダーの板）。
  - 扉の上の札：開いていれば「🔑 予約部屋：「部屋名」開室中 〜21:00」（ランプが緑）、閉まっていれば「🔑 予約部屋　本日 19:00〜「部屋名」」・「… 10/28(水) 19:00〜…」・「（本日の予約なし）」（ランプが赤）。
    これが「本日の予約部屋 / 次の予約」の掲示を兼ねる 🔧。
  - 扉をクリック（タップ）：遠ければ前まで歩いてから（クレーンゲームと同じ）、**合言葉の窓**（閉まっていれば「🔒 現在予約はありません。次は ○○」と［予約表を見る・予約する］）。
  - カレンダーをクリック：その場で予約表（読むだけなので歩かない）。
  - スマホはメニューにも［📅 予約表］［🔑 予約部屋に入る］（PC のオープン部屋の画面は物を置いた以外は変えないので、ボタンは足していない）🔧。
- **入店の画面**✅：「🔑 予約部屋」の欄に［📅 予約表・予約する］［🔑 予約部屋に入る（合言葉）］。予約する・入る前に、その画面の名前と見た目で名前を決め、合言葉が合えばオープン部屋を通らずに予約部屋へ入る。
  - そのため、**このタブで店内にいた（再読み込み）ときだけ自動で入り直し**（その部屋へ）、新しく開いたときは入店の画面を出す（名前と見た目は入っている）🔧。
    v0.4 までは前に来た人は開くとすぐ店内だった。いる部屋は sessionStorage `va:room`（退店・退室で消す）。
- **合言葉の確かめ**はサーバ（`POST /api/rooms/reserved/enter {passphrase}`）。予約した人の鍵と管理者は合言葉なしで入れる。合えば、その予約の間はその鍵を覚える（再読み込みで入り直せる。メモリだけ）。
  間違いは**鍵ごと 10 分に 5 回・IP ごと 20 回**まで（合ったときは数えない。上限に達したら合っていても待たせる）。
- 予約の時間の外は閉まっている（「現在予約はありません / 次は ○○」）。予約部屋で再読み込みして、もう入れないとき（時間が終わった・サーバが再起動して合言葉の記録が消えた）はオープン部屋に入れて理由を出す。
- **予約部屋の中**：上の中央に「🔑 予約部屋「部屋名」〜21:00（予約：名前）」の帯、PC の上のバーに同じ札と［🚪 オープン部屋へ］（v0.5.1 から上のバーの下の帯。§15.1）、スマホの見出しは部屋名（押すと扉の窓）✅。
  同じ場所の扉は「🚪 オープン部屋へ」（押すと確かめてからオープン部屋へ）。

### 14.4 予約の時間の終わり

- 終わる **10 分前・5 分前**に予約部屋のチャットへ「⏰ 予約の時間はあと 10 分です（21:00 に終わります。終わるとオープン部屋に戻ります）」。
- 終わったら（サーバが 5 秒ごとに確かめる。入る前にも確かめる）予約部屋の全員を**オープン部屋へ戻し**（「予約の時間が終わったので、オープン部屋に戻りました」）、
  そのあと予約部屋の**チャット・お知らせ・筐体・クレーンゲームを消す**。合言葉の記録も消す（次の予約には次の予約の合言葉が要る）。
- 予約部屋のチャットは **DB に書かない（メモリだけ）**。終わりで消え、サーバの再起動でも消える。続けての予約に前のチャットは残らない。新しい予約が始まると「🔑 予約部屋「部屋名」が開きました」から始まる。
- 時計はサーバの時刻（テストでは `Config.now` を差し替えて、`syncSlot()` を呼んで確かめる。実時間は待たない）。

### 14.5 やりとり（WebSocket・版）

- `hello` に `proto: 2`（取り決めの版）・`v`（ページの版）・`room`（入りたい部屋）。`welcome` に `room`・`version`（サーバの版）・`reservations`・`reason`（部屋を移された理由）。
  部屋ごとのメッセージ（人・チャット・筐体・お知らせ…）はその部屋の人にだけ送る。部屋を移ると新しい `welcome` が届き、画面はそれで作り直す。予約の一覧が変わると全員に `reservations`。
- **古いページ**（0.4.x がブラウザに残ったタブ。`proto` が無い）には「新しい版になりました。ページを再読み込みしてください」を `kicked` で返して切る（0.4.x の画面はそれを出して、つなぎ直さない）。
  0.5.0 のページは、サーバの版がページの版と違えば右上に「新しい版があります［再読み込み］」を出す。

### 14.6 予約した人（主催）は予約部屋の管理者（✅ ユーザー指定「予約部屋は予約した人が管理者に」）

- **その予約の時間の間、予約部屋の中にいるときだけ**、予約した鍵（主催）は予約部屋の管理者になる（サイトの管理者ではない）。サーバが鍵と予約の時刻で確かめる。つなぎ直し・再読み込みでも同じ鍵なら主催のまま。
- できること（予約部屋の中だけ）：
  - 発言を消す（チャットの ×）・お知らせを流す・消す（予約部屋の大画面とチャットだけに流れる）
  - 筐体を空ける（ほかの人の筐体でも。設定を書き換えるのはサイトの管理者と持ち主だけ）
  - 人を出す：オープン部屋へ戻し、**この予約の間は**その鍵では合言葉でも入れない（`room-banned`。予約が終わると消える）。サイトの管理者は出せない
  - 合言葉を変える（いま中にいる人はそのまま。外にいた人は新しい合言葉が要る）
  - 予約を早めに終える（全員オープン部屋へ戻し、予約部屋の中身を消す。予約の行は終わりの時刻をその時にする）
- できないこと：要望箱・ほかの人のノートやポスターの削除・退室と入室の停止（kick）・オープン部屋やほかの人の予約での操作・回数制限の免除。
  オープン部屋に出ている間・予約の時間が終わったあとは、どの操作も 403。
- **見た目**：名札に「［主催］」、チャットの名前の前に「主催」の印。PC の上のバー（予約部屋のとき。v0.5.1 から上のバーの下の帯）とスマホのメニューに［🛠 部屋の管理］（お知らせ・この部屋の人と［オープン部屋へ戻す］・合言葉を変える・早めに終える）。
  サイトの管理者も予約部屋では同じ窓が使え、今までどおりどの部屋でもすべてできる。
- API：お知らせ・発言の削除は今までの `/api/admin/notices`・`/api/admin/chat/:id`（サーバがその人の部屋と主催かを見る）。筐体は `/api/cabinets/:id/release`。
  `POST /api/room/remove {pid}`・`POST /api/room/passphrase {passphrase}`・`POST /api/room/end`（予約部屋の中の主催者かサイトの管理者）。

### 14.7 予約部屋の時計と残り時間（✅ ユーザー指定「予約部屋は時計を付けて、予約の残り時間を表示してください」）

- 予約部屋では、いまの時刻（日本時間 HH:MM）と予約の残り時間（1 時間以上は「残り 1:23:45」、それより短ければ「残り 12:34」）を出す。
  PC は上のバー（v0.5.1 から上のバーの下の帯）、スマホは見出し（縦・横。横でたたんだときは細い帯に 2 行で）。店内の上には重ねない（タップも邪魔しない）。
- **10 分以下で注意の色（橙）、5 分以下で急ぎの色（赤・点滅）**（終わる前の案内と同じしきい値）。
- 時刻は**サーバの時計**から出す：`welcome` の `serverNow` と、25 秒ごとの ping への `pong` の `serverNow`（送った時刻と受け取った時刻の真ん中にサーバの時刻が来たとみなして差を出す）。
  端末の時計がずれていても残り時間は正しい。予約が取り消された・早めに終えたときは、予約の一覧の知らせと部屋を移る `welcome` ですぐ変わる。
- オープン部屋では残り時間の時計は出さない。扉の札に「🔑 予約部屋：「部屋名」開催中 残り○分」。
- 壁掛けの時計の物は置いていない 🔧（上の中央の部屋名の帯に終わりの時刻がある）。

### 15.2 チャットの残す時間（✅ ユーザー指定「店内チャット24時間とかで消えるようにしましょう」）

- チャットの発言は **24 時間**で消える（`CHAT_TTL_HOURS`。1〜8760 時間）。件数の上限（部屋ごとに新しい 200 件）もそのまま。
- サーバは起動時と 1 分ごとの掃除（sweep）で、残す時間を過ぎた行を消す（オープン部屋は DB の `chat` の表から、予約部屋はメモリから）。
  開いている画面には消えた行ごとに `chat-delete` を送る（0.5.0 の画面もそのまま消せる）。その発言のピン止め（出しっぱなしの吹き出し）も外れる。
- `welcome`（入った・つなぎ直した・部屋を移った）には、掃除の前でも過ぎた発言を入れない。過ぎた発言はピン止めできない（404）。

- DB の形は変えない（行を消すだけ）。0.5.0 へ戻しても、消えた発言は戻らない。

### 16.3 遊ぶ流れとスコアの守り（サーバが手順をなぞって点数を決める ✅ 方針）

- 窓（`GameDialog`。Columns like game を足すときに `Game2048Dialog` から一般化）を開く → `POST /api/games/2048/start` → サーバが**種（32 bit の乱数）**とセッション id を返す → 親が iframe に `{type:'va2048:start', seed, best}` を送り、iframe が新しいゲームを始める。
- iframe は**盤が動いた手だけ**を親に知らせる（`{type:'va2048:move', dir: 0|1|2|3}`、0 上・1 右・2 下・3 左）。「Keep going」（2048 を作ったあと続ける）は `{type:'va2048:keep'}`。
  ゲームオーバーは `{type:'va2048:over', score}`、［New Game］・［Try again］は `{type:'va2048:restart'}`（親が今のゲームを終えて新しい種で始め直す）。親は手の並び（`"0123K…"`）を持つ。
- 親が `POST /api/games/2048/finish {session, moves}` を送るのは：ゲームオーバー・New Game / Try again・窓を閉じる・退店・ページを離れる（`pagehide` で `fetch(…, {keepalive: true})`）。
  1 手も動かしていなければ送らない。**途中でやめても、そこまでの点数を記録する** 🔧（記録はいちばん良いものだけが順位に効くので、損はない）。
- **サーバは種と手の並びから盤を最初からなぞり直して点数を出す**（クライアントの言う点数は使わない）。なぞる処理は `shared/src/game2048.ts`（元の `game_manager.js` と同じ順番・同じ合体の決まり・同じ乱数の使い方）。
  - 手の並びは `0`〜`3` と `K` だけ。**盤が動かない手・終わった後の手・2048 を作っていないのに `K`** があれば `bad-moves`（記録しない）。
  - 速すぎる手は断る：始めてからの時間が `手の数 × 40 ms` より短ければ `too-fast` 🔧。
  - セッションは鍵ごとに 1 つ（新しく始めると前のものは消える。前のゲームは先に finish する決まり）、1 回だけ使える、24 時間で消える。**サーバのメモリだけ**
    （再起動したら途中のゲームは記録できない。そのときは `no-session` で「サーバが再起動したため、このゲームは記録できませんでした」）🔧。
  - 手の並びは 200,000 手まで（この API だけ JSON の上限を 256 KB）。
- 種と手順のなぞり直しで「点数の書き換え」「途中からの盤のでっち上げ」は防げるが、**自動で解くプログラム（AI）に遊ばせることは防げない**（既知の限界）。
- 乱数は mulberry32（32 bit の種 → `[0,1)` の数）。同じ式を `shared/src/game2048.ts` と iframe 側の `js/va_bridge.js` に書く。
  **テストで、同梱した元の JS（`game_manager.js`・`grid.js`・`tile.js` と `va_bridge.js`）を Node の vm で動かし、TS のなぞり直しと点数・盤が一致すること**を、ランダムな手で何百ゲームも確かめる。

### 16.4 ランキング

- 記録は 1 ゲームごとに 1 行（`game_scores`）。順位は**鍵ごとのいちばん良い記録**で並べる（同じ人は 1 行）。同点は先に出した人が上。
- 名前は**その記録を出したときの名前**（後で名前を変えても、その記録の名前はそのまま）。バッジは付けない 🔧。
- 窓のタブ：**総合**・**今月**（日本時間の月）。どちらも上位 50 人と、自分の順位（入っていなくても「あなた：○位 ○点」）。
- ポスターは総合の上位 5 人 🔧。
- 自己ベストで**総合 10 位以内**か**今月 3 位以内**に入ったら、遊んだ人のいる部屋のチャットに system で「🏆 〇〇 さんが 2048 で 12,345 点！（総合 3 位）」🔧。
- 管理者はランキングの窓で記録を 1 行ずつ消せる（不適切な名前など）。消すとその人の次に良い記録が順位に出る。

### 16.5 API・WebSocket・DB

- `GET /api/games` は作らない（ゲームは `shared` の一覧 `GAMES` で決まる。今は `2048` だけ）。知らない `:game` は 404。
- `POST /api/games/:game/start`（店内にいる・その game の筐体に 2 マス以内。鍵ごと 1 分 20 回・IP ごと 1 分 60 回）→ `{session, seed, best}`。`too-far`。
- `POST /api/games/:game/finish {session, moves}`（鍵ごと 1 分 20 回）→ `{score, maxTile, moves, best, newBest, rank: {all, month}}`。`no-session` / `bad-moves` / `too-fast`。
  点数が 0 なら記録しない（`recorded: false`）。店内にいなくても（退店・ページを離れたとき）受け付ける。
- `GET /api/games/:game/ranking?period=all|month`（誰でも。鍵があれば `me`）→ `{entries: [{id, rank, name, score, maxTile, at}], me}`。
- `DELETE /api/admin/games/:game/scores/:id`（サイトの管理者だけ）。
- WebSocket：`welcome` に `rankings: { "2048": 上位 5 }`、変わったら全部の部屋へ `ranking {game, top}`。クライアントから `play {game|null}`、`PlayerView.playing`。
- DB：新しい表 `game_scores(id, game, at, key_hash, pid, name, score, max_tile, moves, ms)` と索引 `(game, score DESC)` を足すだけ（0.5.x へそのまま戻せる）。
  鍵の記録の掃除（来た人の記録は 180 日で消す）とは独立（ランキングは残す）🔧。

### 16.6 実装で決めたこと（DESIGN と違う所・補足）

- **Keep going の守り**：元の `keepPlaying` は状態を見ずに続ける。サーバのなぞり直しと合わせるため、iframe 側も「2048 を作って止まっているときだけ」にした（`CHANGES.md`）。
  なぞり直しの `K` も同じ決まり（続けているのにもう一度 K・終わった後の K は `bad-moves`）。
- **速すぎる手**は `K` を数えない（向きの手だけ）。速さを見てからなぞり直す（でたらめな長い並びを速く断る）。
- **始め直しのずれ**：親が start を送るたびに番号 `gen` を付け、iframe は手に `gen` を付けて返す。親は今の `gen` の手だけ覚える（New Game の直後に古い盤で押した手を混ぜない）。
- **閉じたときの結果**：窓を閉じる・退店で記録したとき（`fetch` の `keepalive`）は、結果を店内の下の帯（toast）に出す。keepalive は 64 KB までなので、それより長い手の並びはふつうに送る。
- **iframe の中の Esc** は親に `va2048:close` を送って窓を閉じる（フォーカスが iframe にあると親にキーが届かないため）。
- **ランキングの窓の順位**：結果の帯の順位は「自己ベストでの順位」。自己ベストを更新しなかったときは「（自己ベストは ○ 点・総合 ○ 位・今月 ○ 位）」と出す。
- **今月の案内**は「今月の自己ベストを更新して今月 3 位以内」（先月のベストが高い人も、今月の 1 位なら案内する）。
- **テストの種**：サーバの種は `crypto` の乱数。テストのときだけ `Config.rng` から作る（2048 まで遊んだ記録 `shared/test/fixtures/win2048.json` を API で通すため）。

- **名前と色について**（✅ ユーザー指定「画面には Columns like game として、宝石の色などは変えてください」）：「Columns（コラムス）」はセガのゲームの名前（このコードは非公式のクローン）なので、

  出典の行は「Original code: columns by J.C. Fields（MIT License）」と GitHub へのリンク。

  マジックジュエル（白）も別の見た目（例：虹色の縁）にしてよい。色の数・並び・ゲームの決まりは変えない（なぞり直しに影響しない）。筐体の画面の絵も新しい色で描く。
- 変えるのは最小限（`CHANGES.md` に書く）：
  - 乱数：`Math.random()` のうちゲームに効くもの（ピースの色 3 つ・マジックジュエル・Height の最初の段）を、サーバの種からの mulberry32 に差し替える（呼ぶ順番は元のまま）。背景の色など見た目だけのものは `Math.random()` のまま。
  - 保存：途中のゲームとローカルのハイスコアを localStorage に残さない（ハイスコアの表・名前の入力は出さず、記録は店のランキング）。オプション（色の数・開始レベル・高さ・モード・ゴースト）は残してよい。
  - 起動・終わり・リセット・ピースを置くたびに親へ postMessage（下の流れ）。Play を押すと親に `va-columns:play {options}` を送り、親が start して種を返してから始まる。
  - **元の不具合の修正**：↓（moveDown）で、ピースが動かなかったときも点が入る（押し続けるとピースが止まって点だけ増える）。**動いたときだけ点を入れる**ようにする。
- **ランキングに載る設定**：モード Standard・色 5（既定）・Height 0 のとき。開始レベルは 1〜12 のどれでもよい（元の表と同じく分けない）。それ以外の設定は**練習**（遊べるが記録しない。窓に「この設定は記録されません」）🔧。
- **スコアの守り（置いた記録のなぞり直し）**：コラムスは時間で落ちてくるが、**井戸の中身は「どのピースを・どの列に・何回回して置いたか」だけで決まる**（積み木は下へ詰まるので、置く高さは列で決まる。
  上の方では横へ自由に動けるので、どの列にも置ける）。そこで iframe はピースが固定されるたびに `{x, rot, bonus, t}`（列・回した回数 0〜2・そのピースの ↓ と落下の点・ゲームの経過秒）を親へ送り、

  - Columns like game：井戸（`#grid` と `#well`）と NEXT が別の canvas なので、**左に井戸、右に NEXT・SCORE・LEVEL・JEWELS を描いた 320 × 400 の 1 枚**にまとめる。
  - WebP の品質 0.6（WebP を書けないブラウザは JPEG）。32 KB を超えたら品質 0.4・0.25 で作り直す。**同じ画面（一時停止など）は送らない**。点数・レベル・状態（遊んでいる・一時停止・ゲームオーバー）は文字で添える。
- **2048**：見る人の窓に `games/2048/index.html?view=1`（`va_bridge.js` に「見るだけ」を足した：キー・スワイプ・ボタンで動かさない・New Game などを隠す・親に知らせない）。
  遊ぶ人の窓は見る人がいる間だけ、0.2 秒ごとに増えた手を `spec-moves`（2,000 字まで）、新しいゲーム・頼まれたときは今のゲームの手を `spec-sync`（45,000 字まで。超えたら「途中からは見られません（次のゲームから）」）。
  サーバは見られている間だけ種（セッション）と手を持ち（保存しない）、**途中から来た人にはサーバが持っている手をまとめて送る**（遊ぶ人に頼むのは最初の 1 回と、番号がずれたとき）。
- **見るきっかけ**：だれかが（同じ部屋で）遊んでいるゲーム筐体をクリック → 窓に［▶ 遊ぶ］と［👀 〇〇 さんのプレイを見る］（見ている人数・許可していなければ押せない）。
  **頭上の名札（🎮）のクリックでも見られる**（遠くても歩かない）。見られている人の名札は「🎮👀2 名前」。
- **遊ぶ人の窓**：見出しの横に「👀 n 人が見ています」と［観戦を許可］（スマホは「👀 n」「観戦」）。許可はサーバのメモリ（再起動で許可に戻る）。切ると今見ている人は終わり（「〇〇 さんが観戦の許可を切りました」）、新しく見られない（`denied`）。
- **終わり**：窓を閉じる・別のゲームにする・歩く・部屋を移る・切断・許可を切る → 見る人に `spec-end`（「〇〇 さんのゲームが終わりました（最後の点数）」）。
  ゲームオーバーは `spec-info`（state = over）で同じ文の帯を出すが、見続けられる（遊ぶ人が次のゲームを始めると続く）。
- **WebSocket の大きさと回数**：`maxPayload` は 48 KB。**4 KB を超えてよいのは入ったあとの `spec-frame`・`spec-sync` だけ**（ほかの種類・入る前は 1009 で切る）。
  観戦の中継（`spec-…`）はふつうのメッセージ（10 秒 80 通）とは別に数え、1 秒 15 通を超えたら切る。画像は 1 秒 `SPECTATE_FPS` 枚まで（超えた分は捨てる）・1 枚 32 KB まで（JPEG / WebP の data URL だけ）。
  **見る人がいない・許可していない・遊んでいないのに来た大きなメッセージは受け取らず**、10 秒に 20 回を超えたら切る。上限：1 人を見られるのは `SPECTATE_MAX_VIEWERS`（8）人まで（`full`）、
  同時に見られている人の合計 `SPECTATE_MAX_STREAMS`（6。`busy`）、`SPECTATE=off` でまるごと止める（`spectate-off`）。見る人は 1 人を見るだけ（別の人を見ると前の人はやめる）。
- **帯域の実測**（Edge ヘッドレス・PC の窓、`game-check.mjs`）：Hextris は 1 枚 平均 2.7 KB（最大 3.6 KB）・1 秒に約 4.5 枚 → 見る人 1 人あたり約 12 KB/秒。
  Columns like game は 1 枚 平均 4.1 KB（最大 4.9 KB）・約 4.2 枚/秒 → 約 17 KB/秒。DESIGN の目安（1 枚 10〜20 KB）より小さい。上限いっぱい（6 人 × 8 人が見る）でも約 0.8 MB/秒。
- **スマホ**：見る人の窓は全画面。2048 の見るだけの iframe は残りの高さいっぱい。

### 16.11 ランキングを左の壁のポスターへ（v0.6.0 のまま、2026-10-30 ✅ ユーザー指定「ゲームのハイスコアボードがちょっと邪魔です。西側の壁際に寄せられますか？」）

- **西側 = 画面の左の壁**（`floor.json` の `left` の壁 = x = 0 の辺。入口と掲示板がある壁）と解釈した。床の立て看板 3 枚（(17,4)・(16,9)・(20,3)）をやめ、
  **左の壁の奥寄り、掲示板の手前の空いている区間 y 0〜6 に壁掛けのポスター 3 枚**（画面の左から 2048・Columns like game・Hextris）。空いた床のマスは通れる。
- **floor.json**：`"rankingWall": { "wall": "left", "from": 0, "to": 6, "games": ["2048", "columns", "hextris"] }`（掲示板 `board` と同じく壁の上の範囲。games は画面の左から右への並び）。
  `loadFloor` が確かめること：範囲が壁の中・入口・大画面・掲示板と重ならない・games は 1〜4 個でゲームの id の形・同じゲームが 2 枚無い・1 枚に壁 1 マス以上。
  床の飾りの `ranking` はやめた（`decor` に書くとエラー）。`rankingSpots()` は rankingWall から作る（id は games の並び順・`index`・`count`・`wall`）。GAMES に無いゲームは出さない。
- **絵**（`render.ts` の `drawRankingWall`）：掲示板（§9）と同じく壁の面に沿わせた紙（壁の傾きに合わせて斜め）・上の 2 か所に画鋲。色はゲームごと（`GAME_LOOKS` の `board`）。
  **高さは壁の 27%〜95%**（掲示板は 6%〜44%）。壁ぎわの植木 (0,0)・(0,5) の葉（壁の高さ 37 ほどまで）に下が隠れない。範囲の両端の余白は手前 0.1 マス・奥の角の側 0.75 マス
  （予約部屋の扉 (2,0) の上の札がスマホで Hextris の 1 位に重なったため）。
  見出しは 2 行（ゲームの名前・「RANKING」）、上位 5 人は 1 人 2 行（大きな順位と名前／右寄せの点数）。幅が狭い（PC 1920×1080 で 1 枚 約 60 px）ので 1 行に並べると名前が 2〜3 文字しか入らないため。
  字は紙の大きさに比例（`font()` の 8px の下限を使わない。スマホは拡大して読む）。
- **3 枚にした理由** 🔧：1 枚の大きな板に 3 列でも 1 列の幅はほぼ同じ（区間の幅は変わらず、得するのは間の 4 px ぐらい）で、共通の見出しを付けるとその分だけ行が低くなる。
  3 枚ならゲームごとの色の紙で見分けやすく、クリックする所もはっきり分かれる。
- **店の名前のネオン**（「VIRTUAL ARCADE」「バーチャルゲームセンター」）は y 4.5 の高さ 62% にあってポスターと重なるので、**掲示板の上（y 9・高さ 73%）へ移した**（掲示板の幅に収まるよう字を少し小さく）。
  そのネオンと重ならないよう、入口の上の看板「入口 ENTRANCE」を高さ 78% → 86% に上げた。
- **描き方**：壁・床は別の canvas に 1 回だけ描く作り（`drawStatic`）なので、ポスターはそこには描かず、掲示板の紙と同じく**毎フレーム、人より先に重ねて描く**（`drawScene`）。
  紙の中身の絵（canvas）は上位・大きさ・画素の比が変わったときだけ作り直す。WebSocket の `ranking` でランキングが変わると次のフレームで描き直される。
- **操作**：当たり判定は紙の四角（壁の傾きに合わせた四角形）。カーソルで紙の縁が光り、札「○○ ランキング　クリックで見る」。クリック・スマホのタップでそのゲームのタブのランキングの窓（歩かずに開く。前と同じ）。
  `#dev` の `__va.ranking(i | 'id')` は壁のポスターの位置（i は画面の左から）、`__va.rankingFace('id')` はいま壁に描いている上位（[名前, 点数]）。
- **確かめたこと**：`game-check.mjs` に、ポスターの並び（掲示板より奥・左下から右上へ）・当たり判定・筐体のまわりに無いこと・空いたマスが通れること・ホバーの指の形・
  ランキングが変わるとその場で描き直されること・スマホで画面の外なら指でドラッグして見回してからタップ、を足した。
